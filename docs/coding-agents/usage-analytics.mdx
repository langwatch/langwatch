Usage rolls up everything your sessions spent. Read your own numbers at [/coding-agents](https://app.langwatch.ai/coding-agents), a project's numbers on the project page, and an organization's numbers on the governance dashboard.

## Your usage at /coding-agents

The personal page opens on this month: what you spent, how many requests you made, and the model you used most, with spend over time and a breakdown by tool underneath.

The **coding-agent usage** card summarizes the last 30 days across your assistants: cost, tokens, active time, and how many sessions you ran. Sessions that reported only metrics still count, so the card is complete even for tools set up with usage-only telemetry.

## Subscription accounts

If your agents run on subscription logins, such as a few Claude Max accounts shared by many agents, the **Subscription accounts** section shows one card per account for the last seven days. The section appears on your personal page and on a project's Sessions page.

Each card shows the agents and top model that ran on the account, the tokens it used so far this week, its cost, and the usage percent the account last reported, with when it was read and when it resets. A card says **Out of usage until** a time while the account is limited.

The percent is the figure the provider reported for the account. Providers publish no token allowance for these plans, so LangWatch never estimates a percent from tokens, and an account that reported none shows no percent.

Claude Code sends its account id (`user.account_uuid`) and Codex sends its own (`user.account_id`), so their accounts show up without setup. A launcher that runs agents on several logins can name each one, and report its usage, with these attributes, on each record or once in `OTEL_RESOURCE_ATTRIBUTES`:

| Attribute | Value |
| --- | --- |
| `langwatch.account.id` | An opaque id for the account. Never an email address. |
| `langwatch.account.name` | The label shown on the card, such as `Work Max`. |
| `langwatch.account.source` | `personal`, `pool` or `computer`. |
| `langwatch.account.usage.percent` | The provider's usage figure, 0 to 100. |
| `langwatch.account.usage.window` | The window it is for, such as `five_hour` or `seven_day`. |
| `langwatch.account.usage.resets_at` | When that window resets, ISO 8601. |
| `langwatch.account.usage.read_at` | When the figure was read, ISO 8601. |
| `langwatch.account.limited_until` | While the account is out of usage, when it can run again, ISO 8601. |

A value on the record wins over the same attribute on the resource. The newest reading per account is the one shown.

## Query it from the command line

The CLI reads the same analytics your pages read:

```bash
langwatch analytics query -m total-cost --group-by metadata.model   # spend per model
langwatch trace search --period 7d                                   # recent traces
langwatch trace export -f jsonl                                      # bulk export for your own analysis
```

You do not have to type these yourself: [give your agent the prompt](/coding-agents/explore-your-usage-with-your-own-agent) and ask your questions in plain language.

## Query it over the API

`GET /api/me/usage` returns your personal rollup: a summary, daily buckets, and a per-model breakdown. The two coding-agent endpoints return the structured data behind the sessions and pull request views:

- `GET /api/coding-agent/sessions/{sessionId}/events` for per-call rows: model calls, compactions, rate limits, tool runs.
- `GET /api/coding-agent/pull-request-usage` for the per-pull-request rollup.

See the [coding agents API reference](/api-reference/coding-agents/overview).

## For admins

The Teams page at `/governance/teams` lists every team's spend and requests over the last 30 days. **Governance > People** at `/governance/people` ranks each person by spend, and a person's row opens their page, personal AI use included. To count spend by cost center, assign people, teams and projects to departments on [People](/ai-governance/people).

**Also check:** [Sessions](/coding-agents/sessions) for the per-session detail behind these rollups, and [Compare provider costs](/coding-agents/compare-provider-costs) to price your real usage mix against other providers.
