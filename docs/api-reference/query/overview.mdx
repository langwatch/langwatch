The Query API runs read-only LangWatchQL `SELECT` statements over your project's analytics datasets. `POST /api/v1/query` runs one statement. `GET /api/v1/query/schema` lists the datasets, columns, and function names your key can query.

The request body is the query itself, and a `200` is the result itself: no envelope, no wrapper object around it. A failure answers with the standard LangWatch error envelope and a real HTTP status, so one parser reads every response.

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/v1/query` | Run one LangWatchQL statement. |
| `GET` | `/api/v1/query/schema` | List queryable datasets, columns, permission gates, and function names. |

## Authentication

Send your LangWatch API key in any one of these forms:

| Form | Header |
|------|--------|
| Token header | `X-Auth-Token: <token>` |
| Bearer | `Authorization: Bearer <token>` |
| Basic | `Authorization: Basic base64(projectId:token)` |

Every request runs against one project. How you name that project depends on the kind of key you hold:

- An **organization API key** reaches several projects, so it must say which one. Name it with an `X-Project-Id: <project id>` header, or send Basic auth as `base64(projectId:token)`. An organization key that names no project is refused with `project_scope_required`.
- A **project key** already names its own project, so it needs no `X-Project-Id` header and ignores one if you send it.

A key scoped to exactly one project may omit the header; any organization key without it is refused.

## Errors

Both endpoints answer with the standard LangWatch error envelope and a real HTTP status. No wrapper sits around it. See [Error Envelope](/ai-gateway/api/errors).

| Status | `code` | When |
|--------|--------|------|
| `400` | `validation_error` | The request body failed validation. |
| `400` | `lwql_unparseable` | The statement is not valid LangWatchQL. |
| `400` | `lwql_not_permitted` | The statement is valid but calls something the policy withholds, for example a function outside the allowlist. |
| `401` | `missing_credentials` | No supported authentication credential was sent. |
| `401` | `invalid_credentials` | The API key is unknown, revoked, or has the wrong secret. |
| `401` | `project_scope_required` | An organization key was sent with no `X-Project-Id` header and no Basic auth project id. Name a project and retry. |
| `403` | `api_key_permission_denied` | The key lacks the `analytics:view` permission. |
| `422` | `query_scan_limit_exceeded` | The statement is valid but would scan more data than the key allows. |

## Response ceilings

A response carries at most 10,000 rows and about 8,000,000 bytes. When a result reaches either ceiling it is cut off there and the response says so: the top-level `truncated` field is `true`, and a `RESULT_TRUNCATED` diagnostic reports the applied row cap in its `meta.maxRows`. Add a tighter `LIMIT` or a narrower time window to bring a large result under the caps.
