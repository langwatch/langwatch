Enabling Langy takes two steps: create the shared `LANGY_INTERNAL_SECRET` secret out-of-band, then opt the agent pod in with `helm upgrade ... --set langyagent.chartManaged=true`. Once the pod is running, Langy is available.

The agent pod is **default off** in the umbrella chart (`langyagent.chartManaged: false` at the umbrella level). The app and the agent both reference a shared `LANGY_INTERNAL_SECRET` Secret that the chart does **not** materialise, so defaulting on would break every existing operator's next upgrade with `CreateContainerConfigError`.

<Info>
**Pairs with:** [Self-hosting overview](/langy/self-hosting/overview), [Environment variables](/langy/self-hosting/environment-variables), [Register the GitHub App](/langy/self-hosting/github-app).
</Info>

<Warning>
A `gvisor` RuntimeClass must exist in the cluster before you enable Langy. With `chartManaged=true` and no `gvisor` RuntimeClass, pods fail to schedule and the chart's render-time guard rejects an empty `runtimeClassName`. See [Self-hosting overview](/langy/self-hosting/overview#hard-requirements).
</Warning>

## Steps

<Steps>
  <Step title="Create the shared secret">
    The app and the agent authenticate to each other with a bearer token. Create the Secret before enabling the pod. 64 hex characters is plenty.

    ```bash title="create-langy-secret.sh"
    kubectl -n langwatch create secret generic langwatch-langyagent-auth \
      --from-literal=LANGY_INTERNAL_SECRET="$(openssl rand -hex 32)"
    ```

    <Warning>
    `LANGY_INTERNAL_SECRET` is a shared credential. Store it in a secrets manager (Vault, AWS Secrets Manager, External Secrets) rather than in `values.yaml` or version control. Never log it.
    </Warning>
  </Step>
  <Step title="Opt the agent in">
    Set `langyagent.chartManaged=true`. This renders the agent Deployment and wires the app's `OPENCODE_AGENT_URL` and `LANGY_INTERNAL_SECRET` automatically.

    ```bash title="enable-langy.sh"
    helm upgrade langwatch ./charts/langwatch -n langwatch \
      -f values.prod.yaml \
      --set langyagent.chartManaged=true
    ```

    After the rollout, the app reaches the agent over cluster DNS at `http://<release>-langyagent:80`. The Service is ClusterIP only, so the agent is never exposed outside the cluster. Once the pod is running, Langy is available in the product.
  </Step>
</Steps>

<Note>
Langy is an optional component. You can disable it again by setting `langyagent.chartManaged=false` and running `helm upgrade`, which removes the agent pod on the next rollout.
</Note>

## Standalone subchart install

The `langyagent` subchart can also be installed on its own, for example if you run the control plane and the agent as separate releases:

```bash title="install-langyagent-standalone.sh"
helm install langyagent ./charts/langyagent -n langwatch \
  -f langyagent-values.yaml
```

When you install it standalone, the umbrella chart does not wire the app for you. Set `OPENCODE_AGENT_URL` on your control-plane deployment yourself so the app can reach the agent, and make sure both reference the same `LANGY_INTERNAL_SECRET`.

## Chart values a self-hoster tunes

The values below are the ones you are most likely to change. See the [environment variables reference](/langy/self-hosting/environment-variables) for what each maps to at the process level.

| Value | Purpose |
|---|---|
| `chartManaged` | Render and enable the agent pod. Default `false` in the umbrella. |
| `environment` | Deployment environment. Gates the dev-only isolation bypass; keep production-like. |
| `image.tag` | Agent image version. |
| `replicaCount` | Keep at `1`. A render-time guard blocks more until conversation-sticky routing exists. |
| `manager.maxWorkers` | Max concurrent opencode subprocesses before the pod returns 503. Default 20. |
| `manager.workerIdleMs` | Idle-worker reap timeout. Default 600000 (10 min). |
| `manager.readinessTimeoutMs` | Wait for a spawned worker's opencode to bind. Chart sets 60000 for gVisor cold boot. |
| `resources` | CPU and memory requests and limits. Size for your concurrency (500m to 2 CPU / 1 to 4Gi). |
| `secrets.existingSecretName` | Name of the `LANGY_INTERNAL_SECRET` Secret you created (`langwatch-langyagent-auth`). |
| `secrets.internalSecretKey` | The key inside that Secret (`LANGY_INTERNAL_SECRET`). |
| `runtimeClassName` | `gvisor` (required). Setting `""` opts out of pod-to-host sandboxing; not recommended. |
| `networkPolicy.allowExternalHttps` | Allow outbound `:443` for `git`/`gh`/`npm`. Default `false`. |
| `networkPolicy.privateExcept` / `privateExceptV6` | CIDRs to exclude from the private-range egress deny (add any non-RFC1918 VPC CIDR). |
| `egress.fqdnFloor` | Operator always-allowed FQDNs. Default `github.com,api.github.com,codeload.github.com`. |
| `egress.enforceFloor` | Make the floor a hard ceiling for projects with no allow-list. Default `false` (monitor-only). |
| `mirror.traceEndpoint` / `mirror.existingSecretName` | Operator mirror lane (off unless both set). |
| `nodeSelector` / `affinity` / `tolerations` | Pin the pod, for example to an opt-in public-subnet node group. |
| `podDisruptionBudget` | Optional PDB for the single replica. |
| `workspaceVolume` | The writable workspace `emptyDir`. |

<Warning>
The pod's `podSecurityContext` and `containerSecurityContext` are opinionated (the manager runs as root with exactly five added capabilities to do per-worker UID isolation) and are documented as not to be weakened. See [The sandbox](/langy/security/sandbox).
</Warning>
