## Turn on Dashboards

Dashboards is a product in the product switcher at the top left of LangWatch.
It sits behind the `release_dashboards` feature flag, which is off by default.

## Your first board

Opening Dashboards takes you to the first board you created. If you can see no
board yet, LangWatch makes one for you, called "My dashboard", that only you can
see.

## The sidebar

The sidebar has a quick search box and the list of saved boards, grouped into
Mine, Team and Organisation. The **+** button creates a new board.

## Start from a template

A board with nothing on it offers its templates under "Start from a template":
the Agent Flight Deck, then one template for every section of the question
picker ("What happened?", "What changed?" and so on). Choosing one creates a new
board named after it (numbered "Agent Flight Deck 2" and so on if the name is
taken), visible only to you, with a widget answering each question in that
section. A widget whose data is not set up yet says what is missing and links to
the page that sets it up, such as evaluations, scenarios or feedback.

The Agent Flight Deck holds ten widgets:

- Status
- Throughput, latency and errors
- Cost efficiency
- Failure intelligence
- Scenario results
- Quality signal
- User feedback
- Gateway routing
- Your coding agents
- Most impactful traces

A new board is yours like any other: every widget on it can be edited,
duplicated, moved, resized or deleted, and nothing you change affects the
template.

## Period and grain

Every board has a period, from one hour to one year, defaulting to 30 days,
and a grain: auto, hour, day or week. Every widget on the board reads over that
period and grain.

## Building your own board

On a board, you can rename it and add a description. **Add chart** opens the
widget editor, where you write the widget's code and its LangWatchQL queries.
Move a widget by its drag handle and resize it from its corner. Each widget's
menu offers:

- **Edit**: opens the widget editor on that widget's code and queries.
- **Duplicate**: adds a copy at the bottom of the board.
- **Delete**: removes the widget.

A board's visibility is Only me, Team or Organisation. Only the board's
creator or a project admin can change its visibility or delete it.

## Asking questions

The question picker lists suggested questions. Picking one sends a detailed
prompt to Langy, with the board as context. Langy answers in its own panel.
Nothing is added to the board. There is also an ask bar at the top of every
board for asking Langy about that board directly. Both need Langy to be enabled
for your project.

## How the data is read

All board data is read with LangWatchQL, LangWatch's query layer over your
traces, evaluations and cost data.

## Build boards from your own AI agent

Your coding assistant can build and edit LangWatch dashboards for you, through
the [LangWatch MCP server](/integration/mcp).

### Connect the MCP server

Connect Claude Code, Cursor, or another MCP-capable assistant to LangWatch
first. Follow the [LangWatch MCP Server setup guide](/integration/mcp) to add
the server and set your API key.

### Dashboard tools

Once connected, your agent has these dashboard tools:

- `platform_list_dashboards`: list every dashboard in the project.
- `platform_get_dashboard`: read one dashboard, including its widgets.
- `platform_create_dashboard`: create a new, empty dashboard.
- `platform_rename_dashboard`: rename a dashboard.
- `platform_delete_dashboard`: delete a dashboard and its widgets.
- `run_query`: run one read-only LangWatchQL (LWQL) statement and see the rows
  it returns. Use this to check a query before it goes into a widget.
- `add_dashboard_widget`: create a custom widget and add it to a dashboard.

### The widget definition format

A widget has two parts:

- **`code`**: a TSX source file. It runs sandboxed in the browser and renders
  the widget's chart or panel.
- **`queries`**: up to 8 named LangWatchQL statements the code can read from.
  Pass them as `{ "<name>": "<LWQL SQL>" }`, or as a list of `{ name, sql }`
  entries.

Ask your agent to validate each query with `run_query` before it calls
`add_dashboard_widget`. A query only actually runs once the widget renders
inside the sandbox, so catching a mistake in the SQL earlier, with
`run_query`, is faster than catching it on the dashboard.

### The LW widget API

Inside `code`, a global `LW` object gives the widget everything it needs:

- `LW.dashboardContext`: the dashboard's current time window, granularity,
  timezone and theme.
- `LW.params`: the widget's own author-declared parameter values.
- `LW.theme`: the dashboard's current colour theme (`"light"` or `"dark"`).
- `LW.query(name, params?)`: runs one of the widget's named queries and
  returns its rows.
- `LW.useChartQuery(name, params?)`: the React hook version of `LW.query`.
  Gives `data`, `isLoading`, `isFetching`, `isError`, `error`, `status`, and
  `refetch`, and refetches automatically when the dashboard's time window or
  granularity changes. Use this instead of `LW.query` in most widgets.
- `LW.setHeight(px)`: resizes the widget's frame once its content's height is
  known.
- `LW.onDashboardContextChange(callback)` / `LW.useDashboardContext()`:
  subscribe to, or read, the dashboard's live context.
- `LW.useParams()`: read the widget's author-declared parameter values.
- `LW.error(err)`: report an error without throwing.
- `LW.navigate(target, params?)`: navigate the host to an allowlisted target,
  such as a trace list or a single trace.

### Example prompt

```
Add a widget to my Agent health board that shows p95 latency by model
for the last 7 days.
```

Your agent will validate the LWQL with `run_query`, write the widget's TSX
code against `LW.useChartQuery`, and call `add_dashboard_widget` to add it to
the board.
