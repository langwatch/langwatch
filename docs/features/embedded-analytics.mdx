## Export Analytics with REST Endpoint

LangWatch offers you the possibility to build and integrate LangWatch graphs on your own systems and applications, to display it to your customers in another interface.

In the LangWatch dashboard, use the custom chart builder to plot any data LangWatch collects or generates, and to set how it is displayed. You then use our REST API to fetch the graph data.

**Usage:**
You will need to obtain your JSON payload from the custom graph section in our application. You can find this on the Analytics page > Custom Reports > Add chart.

    1. Pick the custom graph you want to get the analytics for.
    2. Prepare your JSON data. Make sure it is the same format that is showing in the LangWatch application.
    3. Use the `curl` command to get you analytics data. Here is a basic template:

```bash
# Set your API key and endpoint URL
API_KEY="your_langwatch_api_key"
ENDPOINT="https://app.langwatch.ai/api/v1/analytics"

# Use curl to send the POST request, e.g.:
curl -X POST "$ENDPOINT" \
    -H "X-Auth-Token: $API_KEY" \
    -H "Content-Type: application/json" \
    -d @- <<EOF
    {
     "startDate": 1708434000000,
     "endDate": 1710939600000,
     "timeZone": "UTC",
     "filters": {},
     "series": [
       {
         "metric": "metadata.user_id",
         "aggregation": "cardinality"
       }
     ],
     "timeScale": 1
   }
EOF
```

    4. Execute the `curl` command. If successful, LangWatch will return the custom analytics data in the response.

## Filters

`filters` narrows the query the same way the filter sidebar narrows the dashboard. Each key is a filter field. Most fields take a list of the options to keep. Keyed fields, such as `metadata.value`, take an object whose key is what the filter selects by:

```json
{
  "filters": {
    "traces.error": ["true"],
    "metadata.user_id": ["user-123"],
    "metadata.value": { "environment": ["production"] }
  }
}
```

Send the option's value (`field` in the filter options), not the label shown in the interface. `traces.error`, `annotations.hasAnnotation` and `evaluations.passed` accept only `"true"` and `"false"`. A label such as `"Traces with error"` is refused with a 422 and the code `analytics_filter_value_unsupported`, which names the field and lists the values it accepts.

`metadata.value` needs its metadata key, and `events.metrics.value` needs its event type and metric key. Sent as a plain list, they are refused with the code `analytics_filter_key_required` and an example of the nested shape. An unknown filter field is refused too, with the list of accepted fields.
