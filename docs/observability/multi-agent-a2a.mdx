---
title: "Multi-agent traces across A2A"
description: "See every agent of an A2A call chain in one trace, with the calls, errors, latency and cost between them."
---

When one agent calls another over the Agent2Agent (A2A) protocol, LangWatch shows the whole chain as one trace. Open the trace and pick the **Agents** tab to see which agent called which, how often, how many calls failed, how long they took and what each agent cost.

## How spans join one trace

Spans from different agents join the same trace when the caller sends the W3C `traceparent` header on its A2A request and the callee continues that context. Most OpenTelemetry HTTP instrumentations do this for you. If the callee starts a new trace instead, its spans land in a separate trace and the graph shows only one side.

A span whose parent is not in the trace is still drawn as an agent, marked "Caller not in this trace", so a missing `traceparent` is easy to spot.

## Attributes LangWatch reads

Each span belongs to the agent named by `gen_ai.agent.name` (or `gen_ai.agent.id`). A span without one belongs to its parent's agent. When `service.name` changes under a span with no agent, the new service becomes its own node.

A span is marked as an A2A call when it carries `a2a.*` attributes, such as `a2a.method`, `a2a.context.id`, `a2a.task.id` and `a2a.task.state`. Those spans get an **A2A** label in the span tree, and the edge they sit on is marked A2A in the graph.

## The call graph

Each node is an agent, with its span count and the cost of its own LLM spans, so a parent is never charged for its children. Each edge counts the calls from one agent to another, with errors, average and maximum latency. Click an edge to open its first call in the span details.

The **Agents** tab appears only when a trace has more than one agent.
