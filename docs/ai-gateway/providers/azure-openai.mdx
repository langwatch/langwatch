## Add the credential

Open **Settings > Model Providers**, click **Add Model Provider** and select **Azure OpenAI**. Give the row a name, pick the organization, team or project it belongs to, and fill in:

| Field | Value |
|---|---|
| `AZURE_OPENAI_API_KEY` | The key of your Azure OpenAI resource. |
| `AZURE_OPENAI_ENDPOINT` | The resource endpoint, for example `https://acme-eu.openai.azure.com`. |
| `AZURE_OPENAI_API_VERSION` | The `api-version` query parameter. Set a version that serves your models, for example `2025-01-01-preview`. With an older version Azure answers `404 Resource not found`. |

Save the row. Every virtual key whose scope can see the row can now dispatch to it, unless the key restricts its providers. See [Virtual keys](/ai-gateway/virtual-keys#create-a-virtual-key).

Switch on **Use API Gateway** when your Azure OpenAI traffic goes through Azure API Management. The form then asks for `AZURE_API_GATEWAY_BASE_URL` and an optional `AZURE_API_GATEWAY_VERSION` (default `2024-05-01-preview`) instead of the endpoint.

## Deployments and model names

Azure serves models through deployments that you name yourself. The gateway uses the model id as the deployment name: `azure/gpt-5-mini` calls the deployment named `gpt-5-mini` on the resource.

Add each deployment name under **Custom Models** on the row. A request for a model that is not on the row's list is rejected before it reaches Azure with `400 provider_config_invalid` and the message `This model provider is not configured to serve "gpt-5-mini"`.

To keep application code on generic names when your deployment names differ, map them on the key with `model_aliases`, for example `{"gpt-5-mini": "azure/acme-mini-eu"}`. See [Model aliases](/ai-gateway/model-aliases).

## Send a request

```bash
curl https://gateway.langwatch.ai/v1/chat/completions \
  -H "Authorization: Bearer $LANGWATCH_VIRTUAL_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "azure/gpt-5-mini",
    "messages": [{"role": "user", "content": "Say hi in one word"}]
  }'
```

The gateway sends the request to `<endpoint>/openai/deployments/<deployment>/chat/completions?api-version=<version>` with the key in the `api-key` header.

## Endpoints

| Endpoint | Served |
|---|---|
| `POST /v1/chat/completions` | Yes |
| `POST /v1/responses` | Yes |
| `POST /v1/messages` | Yes, translated |
| `POST /v1/embeddings` | Yes |
| `POST /v1/images/generations`, `POST /v1/images/edits` | Yes, non-streaming. See [Images](/ai-gateway/api/images) |
| `GET /v1/models` | Yes, the names under Custom Models |

## More than one resource

Create one row per Azure resource and give each a **Routing handle**, for example `eu` and `us`. `eu/gpt-5-mini` pins the request to that resource. A routing policy sets the order a key tries them in. See [Routing policies](/ai-gateway/governance/routing-policies).
