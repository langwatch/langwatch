## Add the credential

Open **Settings > Model Providers**, click **Add Model Provider** and select **Custom (OpenAI-compatible)**. Give the row a name, pick the organization, team or project it belongs to, and fill in:

| Field | Value |
|---|---|
| `CUSTOM_BASE_URL` | The endpoint, for example `https://inference.acme.internal/v1`. A trailing `/v1` is accepted. |
| `CUSTOM_API_KEY` | Optional. Sent as `Authorization: Bearer` when set. |

Save the row. Every virtual key whose scope can see the row can now dispatch to it, unless the key restricts its providers. See [Virtual keys](/ai-gateway/virtual-keys#create-a-virtual-key).

Add the models the endpoint serves under **Custom Models** on the row. `GET /v1/models` lists those names.

The endpoint must be reachable from the gateway. The gateway always refuses link-local and cloud metadata addresses, and refuses private and loopback addresses when it runs with `BLOCK_LOCAL_HTTP_CALLS=true`.

On LangWatch Cloud the endpoint must use `https`: a hosted gateway refuses to start without `REQUIRE_HTTPS_CUSTOM_ENDPOINTS=true`, and with it an `http` endpoint is refused. A self-hosted gateway accepts `http` while that setting stays `false`.

## Model names

Write `custom/<model>`, for example `custom/qwen3-14b`. Give the row a **Routing handle** when you have several custom endpoints: `acme-gpu/qwen3-14b` pins that row.

## Send a request

```bash
curl https://gateway.langwatch.ai/v1/chat/completions \
  -H "Authorization: Bearer $LANGWATCH_VIRTUAL_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "custom/qwen3-14b",
    "messages": [{"role": "user", "content": "Say hi in one word"}]
  }'
```

## Endpoints

| Endpoint | Served |
|---|---|
| `POST /v1/chat/completions` | Yes |
| `POST /v1/messages` | Yes, translated |
| `POST /v1/embeddings` | Yes, when the endpoint serves it |
| `GET /v1/models` | Yes, the names under Custom Models |

Streaming, tools and other features depend on what the endpoint implements. A feature the endpoint does not support comes back as the endpoint's own error.
