## Add the credential

Open **Settings > Model Providers**, click **Add Model Provider** and select **Bedrock**. Give the row a name, pick the organization, team or project it belongs to, and fill in:

| Field | Value |
|---|---|
| `AWS_ACCESS_KEY_ID` | The access key id of an IAM user or role session. |
| `AWS_SECRET_ACCESS_KEY` | The matching secret access key. |
| `AWS_REGION_NAME` | The region the models are enabled in, for example `us-east-1`. |

Save the row. Every virtual key whose scope can see the row can now dispatch to it, unless the key restricts its providers. See [Virtual keys](/ai-gateway/virtual-keys#create-a-virtual-key).

All three fields are required.

## Model names

Write `bedrock/<model id>` with the Bedrock model id or inference profile id, for example `bedrock/us.anthropic.claude-haiku-4-5-20251001-v1:0`. The gateway does not infer Bedrock from a bare name. Add the ids you use under **Custom Models** on the row so that `GET /v1/models` lists them.

Map friendly names on the key with `model_aliases`, for example `{"claude-haiku": "bedrock/us.anthropic.claude-haiku-4-5-20251001-v1:0"}`. See [Model aliases](/ai-gateway/model-aliases).

## Send a request

```bash
curl https://gateway.langwatch.ai/v1/chat/completions \
  -H "Authorization: Bearer $LANGWATCH_VIRTUAL_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "bedrock/us.anthropic.claude-haiku-4-5-20251001-v1:0",
    "messages": [{"role": "user", "content": "Say hi in one word"}]
  }'
```

## Endpoints

| Endpoint | Served |
|---|---|
| `POST /v1/chat/completions` | Yes |
| `POST /v1/messages` | Yes, translated |
| `POST /v1/embeddings` | Yes, for Bedrock embedding models |
| `GET /v1/models` | Yes, the ids under Custom Models |

`cache_control` blocks on Anthropic models become Converse `cachePoint` markers, and the cache token counts come back in `usage`. See [Caching passthrough](/ai-gateway/caching-passthrough).

Model access is enabled per account and region in the AWS console. A 403 from Bedrock that says the account has no access to the model means that opt-in is missing.
