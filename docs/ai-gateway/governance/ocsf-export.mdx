## What the export contains

LangWatch writes one OCSF record per trace that arrives through an [ingestion source](/ai-governance/ingestion-sources). Each record is an OCSF 1.1 API Activity event (`class_uid` 6003, `category_uid` 6). A record linked to an anomaly alert has `severity_id` 4 (Medium); every other record has `severity_id` 1 (Informational).

Records are stored with no expiry. Your SIEM pulls them by cursor, on its own schedule, and keeps its own watermark.

## Endpoint and auth

The export is the tRPC query `governance.ocsfExport`. Call it as a `GET` on `/api/trpc/governance.ocsfExport` with the input JSON in the `input` query parameter.

| Requirement | Value |
|---|---|
| Plan | Enterprise |
| Permission | `complianceExport:view`. Organization admins hold it; grant it to another role through a custom role. See [RBAC](/ai-gateway/rbac) |
| Auth | The session cookie of a signed-in user. API keys and virtual keys are not accepted |
| Tenancy | The permission is checked against `organizationId`. A call for an organization where the caller does not hold it is refused |

## Input

| Field | Type | Default | Purpose |
|---|---|---|---|
| `organizationId` | string | required | The organization to export |
| `sinceMs` | integer | `0` | Return records with `eventTimeMs` after this UNIX millisecond watermark |
| `sinceEventId` | string | none | Paired with `sinceMs`: the `eventId` of the last record you received, so records that share a millisecond are neither skipped nor repeated |
| `limit` | integer | `500` | Page size, 1 to 1000 |

## Output

The HTTP response wraps the procedure result under `result.data.json`. The result is:

```json
{
  "events": [
    {
      "eventId": "evt_01HZX9N...",
      "ocsfSchemaVersion": "1.1.0",
      "traceId": "trace_...",
      "sourceId": "src_...",
      "sourceType": "otel_generic",
      "classUid": 6003,
      "categoryUid": 6,
      "activityId": 6,
      "typeUid": 600306,
      "severityId": 1,
      "eventTimeMs": 1748678421123,
      "actorUserId": "user_...",
      "actorEmail": "jane@acme.com",
      "actorEnduserId": "",
      "actionName": "web_search",
      "targetName": "anthropic/claude-sonnet-4",
      "anomalyAlertId": "",
      "rawOcsfJson": "{...}"
    }
  ],
  "nextCursor": 1748678421123,
  "nextCursorCompound": { "eventTimeMs": 1748678421123, "eventId": "evt_01HZX9N..." }
}
```

`rawOcsfJson` is the full OCSF 1.1 event as a JSON string. The other fields are the columns your SIEM filters on. `actionName` is the tool the trace invoked, or `trace.recorded` for a trace with no tool call. `anomalyAlertId` is empty when no anomaly rule matched. An organization with no ingestion source yet returns `{ "events": [], "nextCursor": null, "nextCursorCompound": null }`.

## Pagination

Persist `nextCursorCompound` after each page. On the next pull, pass its `eventTimeMs` as `sinceMs` and its `eventId` as `sinceEventId`. Records are ordered by `eventTimeMs` ascending.

A page that returns `limit` records may be followed by more. Pull again at once until a page returns fewer than `limit` records, then wait for your next scheduled run.

## Example

```bash
INPUT='{"json":{"organizationId":"YOUR_ORGANIZATION_ID","sinceMs":0,"limit":500}}'

curl -G "https://app.langwatch.ai/api/trpc/governance.ocsfExport" \
  --data-urlencode "input=$INPUT" \
  -H "Cookie: YOUR_SESSION_COOKIE"
```

Replace `YOUR_SESSION_COOKIE` with the cookie of a browser session signed in as a user who holds `complianceExport:view`. Forward `events[]` to your SIEM's ingest API, then store `nextCursorCompound` for the next run.

**Also check:** [Anomaly rules](/ai-governance/anomaly-rules) for what sets `anomalyAlertId`, and [Retention](/ai-gateway/governance/retention) for how long the source traces are kept.
