The `model` field accepts three forms. Each one tells the gateway a different amount about where the request goes.

| Form | Example | Where the request goes |
|---|---|---|
| Bare model | `"model": "gpt-5-mini"` | The provider on the key that serves that model. The gateway infers the provider. |
| Provider and model | `"model": "openai/gpt-5-mini"` | A provider of that kind on the key. |
| Instance handle and model | `"model": "europe/claude-sonnet-5"` | The one provider instance that carries the handle `europe`. |

A fourth kind of name, an alias, is a name a routing policy maps to one of the forms above. See [Model Aliases](/ai-gateway/model-aliases).

## Resolution order

The gateway reads the `model` string once, in this order. The first step that matches decides.

1. **Alias.** If the routing policy maps the exact string to a target, the target replaces it. The target is then read with the same rules as a request, so an alias can point at any of the three forms.
2. **Instance handle.** If the text before the first `/` is a routing handle on one of the key's providers, the request is pinned to that provider instance. The rest of the string is the model id.
3. **Provider family.** If the text before the first `/` is a provider family the gateway knows, the request goes to a provider of that kind. The rest of the string is the model id, including any further `/`.
4. **Bare model.** Otherwise the whole string is the model id, slashes included, and the gateway infers the provider from it.

The prefix is removed before the request leaves. A provider never receives `openai/gpt-5-mini` as a model name.

## Provider families

`openai`, `anthropic`, `azure`, `bedrock`, `vertex`, `gemini`, `xai`, `groq`, `cerebras`, `deepseek`, `voyage`, `elevenlabs`, `cloudflare`, `custom`, `openai_codex`.

The alternative spellings that SDKs emit are accepted too: `azure_openai`, `aws_bedrock`, `vertex_ai`, `google_vertex`, `google_gemini`. The family is case-insensitive, so `OpenAI/gpt-5-mini` works.

A family names a kind of provider, not one instance. If the key reaches two Anthropic providers, `anthropic/claude-sonnet-5` matches both and the first one in the key's provider order serves the request. The others stay available for failover. Use an instance handle to choose one.

The provider order is the order in the key's routing policy. A key with no policy orders its providers by the global fallback priority set on each provider, then by creation date.

## How the gateway infers the provider for a bare model

For a bare model name the gateway tries four steps and stops at the first one that leaves at least one provider:

1. **Providers that declare the model.** A custom provider lists the models it serves, and a hosted provider ships a catalog. This is what makes a declared model routable without a prefix.
2. **The vendor in the name.** A short built-in table maps a prefix to the vendor that originated it. This is the safety net for a model newer than the shipped catalog.
3. **Providers with no model list.** A provider with no model list cannot be ruled out by a model it does not list.
4. **A key with one provider.** With one provider there is no choice to make, so the gateway forwards any model name to it.

If all four steps leave no provider, the request is refused with `model_not_recognized`.

The vendor table in step 2:

| Model name starts with | Provider |
|---|---|
| `claude-` | `anthropic` |
| `gpt-`, `o1-`, `o3-`, `o4-`, `chatgpt-`, `text-embedding-`, `dall-e-`, `whisper-`, `tts-` | `openai` |
| `gemini-` | `gemini` |

Bedrock and Vertex are not in the table. Write `bedrock/anthropic.claude-…` or `vertex/…`, or use an alias, to reach a Claude or Gemini model through them.

### Model ids that contain a slash

A model id can contain a `/` of its own, which is normal for self-hosted servers and proxies: `stealth/ox-alpha`, `meta-llama/Llama-3-70B`. The gateway reads the first segment as a prefix only when it is a routing handle or a provider family. Once you declare `stealth/ox-alpha` on the provider that serves it, `"model": "stealth/ox-alpha"` works as written.

One case still needs a prefix. A model whose first segment spells a provider family, for example `openai/my-finetune` on a self-hosted server, is read as the `openai` family. Write `custom/openai/my-finetune` instead.

## Instance handles

A routing handle is a name you give to one model provider. Set it on the provider in **Settings → Model Providers**. It is unique inside your organization, so `europe/claude-sonnet-5` names the same provider from every key that reaches it.

Use a handle when you run more than one provider of the same kind and want to choose between them in the request. For example, a European and a United States Anthropic account.

Rules for a handle:

- Lowercase. It starts with a letter or a number, then letters, numbers, hyphens and underscores, up to 32 characters.
- It cannot be a provider family name, or one of the reserved words `azure_openai`, `aws_bedrock`, `vertex`, `google_vertex`, `google_gemini`, `cloudflare`, `mp`.
- Renaming a handle is a breaking change for every caller that uses it. Requests naming the old handle stop reaching that provider immediately.

A handle pins one provider instance. When the key cannot reach that instance, the request is refused with `model_provider_not_bound` naming the handle. No other provider serves it in its place.

`GET /v1/models` lists the models of a provider that has a handle under the handle-qualified name, so `europe/claude-sonnet-5` appears rather than `claude-sonnet-5`. See [API: `GET /v1/models`](/ai-gateway/api/models).

## Declaring the models a provider serves

Hosted providers already declare their models, so `gpt-5-mini` and `claude-sonnet-5` route without setup.

For a **Custom (OpenAI-compatible)** provider, add the models under **Custom models** on the provider. That is what lets a caller send the bare model name instead of `custom/` in front of it, and what puts the model in `GET /v1/models`.

A key with one provider does not need this. Every model name is forwarded to that provider.

## When a name does not resolve

Every refusal is a JSON error with `error.code`, and the HTTP status is fixed per code.

| `error.code` | HTTP | Cause |
|---|---|---|
| `missing_model` | 400 | The request names no model. The message says where this endpoint expects it. |
| `model_not_recognized` | 400 | A bare model name that no provider on the key serves, and the key holds more than one provider. |
| `model_provider_not_bound` | 400 | The request named a provider family or a handle that this key cannot reach. Also returned when a request arrives on a provider-native route (`/v1/messages`, the Gemini `/v1beta` route) and the key has no provider of that vendor. |
| `model_not_allowed` | 400 | The model resolved, but the key's `models_allowed` list, its provider access, or its routing policy excludes it. |
| `no_provider_configured` | 400 | The organization has no model provider at all. Add one in **Settings → Model Providers**. |

`model_provider_not_bound` and `model_not_recognized` list the prefixes the key accepts, so the caller can correct the request from the message. The list is capped at ten names and is also in `error.meta.options`.

```json
{
  "error": {
    "code": "model_provider_not_bound",
    "message": "The \"bedrock\" provider is not reachable from this key's scope, so no credential is configured for it. This key reaches \"anthropic\", \"openai\", \"europe\". Ask the key's owner to add the provider, or send the request to one of those."
  }
}
```

```json
{
  "error": {
    "code": "model_not_recognized",
    "message": "No provider on this key serves the model \"private-build\". This key reaches \"anthropic\", \"openai\". Name the provider in the model string, or declare the model on the provider that serves it."
  }
}
```

`models_allowed` plays no part in choosing a provider. It judges the model the request resolves to, in both spellings: an entry of `gpt-5-mini` and an entry of `openai/gpt-5-mini` allow the same model.

**Also check:** [Troubleshooting](/ai-gateway/troubleshooting) for the full error index.

## Choosing a form

<Steps>
  <Step title="One provider on the key">
    Use the bare model name.
  </Step>
  <Step title="Several providers, different models">
    Use the bare model name. Each provider declares its own models, so the name is enough.
  </Step>
  <Step title="Several providers of the same kind">
    Give each one a routing handle and use it: `europe/claude-sonnet-5`.
  </Step>
  <Step title="A stable name you can repoint later">
    Use an alias in the routing policy. See [Model Aliases](/ai-gateway/model-aliases).
  </Step>
  <Step title="Failover between providers">
    Name a model that more than one provider on the key serves. The gateway carries the same model name to the next provider in the chain. See [Fallback Chains](/ai-gateway/providers/fallback-chains).
  </Step>
</Steps>
