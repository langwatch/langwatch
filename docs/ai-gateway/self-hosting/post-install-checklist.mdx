---
title: Post-install checklist
description: Verify a self-hosted LangWatch AI Gateway with curl, from the pod to a completed chat request.
---

Run these checks in order after `helm install`. Each one builds on the previous one, so the first failure tells you which layer to fix. The commands assume the release name `langwatch` and the namespace `langwatch`.

## 1. The pod is running

```bash
kubectl -n langwatch rollout status deploy/langwatch-gateway
kubectl -n langwatch logs deploy/langwatch-gateway --tail 50
```

Expected: `deployment "langwatch-gateway" successfully rolled out`, and a log line `aigateway_starting` with `addr: ":5563"`.

A pod in `CreateContainerConfigError` is missing the Secret or one of its keys. See [Helm chart](/ai-gateway/self-hosting/helm#common-failures).

## 2. The process answers in-cluster

```bash
kubectl -n langwatch run curl --rm -it --image=curlimages/curl --restart=Never \
  -- curl -sS http://langwatch-gateway/healthz
```

Expected:

```json
{"status":"ok","version":"local","uptime_s":42.1}
```

`version` carries the `ENVIRONMENT` value, `local` unless you set it.

## 3. The gateway reaches the control plane

```bash
kubectl -n langwatch run curl --rm -it --image=curlimages/curl --restart=Never \
  -- curl -sS http://langwatch-gateway/health
```

Expected:

```json
{"status":"ok","checks":{"gateway":"ok","control_plane":"ok"}}
```

A `503` with `"control_plane":"unreachable for Ns"` means one of two things: the gateway cannot reach `LW_GATEWAY_BASE_URL`, or `LW_GATEWAY_INTERNAL_SECRET` differs between the app and the gateway pods. The probe runs every 15 seconds and the verdict flips after 60 seconds without a success, so wait one minute after a fix before you read it again. The log line `statusprobe_control_plane_unreachable` on the gateway pod carries the underlying error.

Confirm which control plane URL the pod resolved:

```bash
kubectl -n langwatch run curl --rm -it --image=curlimages/curl --restart=Never \
  -- curl -sS http://langwatch-gateway/debug/control-plane
```

Expected: `{"control_plane_base_url":"http://langwatch-app:5560"}`.

## 4. The public hostname serves TLS

```bash
curl -sS https://gateway.acme.com/health
```

Expected: the same `{"status":"ok",...}` body as step 3. A certificate error means the `gateway-tls` Secret is not issued yet; see [DNS and TLS](/ai-gateway/self-hosting/dns-and-tls).

## 5. Authentication rejects a missing key

```bash
curl -si https://gateway.acme.com/v1/models
```

Expected: `HTTP/2 401`, an `X-LangWatch-Gateway-Version` header, and this body:

```json
{"error":{"type":"invalid_api_key","code":"invalid_api_key","message":"missing API key; supply Authorization: Bearer <key>, x-api-key, x-goog-api-key, or xi-api-key header"}}
```

## 6. A virtual key lists models

Add a model provider credential and create a virtual key in the LangWatch UI. See [Providers](/ai-gateway/providers/overview) and [Virtual keys](/ai-gateway/virtual-keys).

```bash
export LW_VK=vk-lw-YOUR_VIRTUAL_KEY

curl -sS https://gateway.acme.com/v1/models \
  -H "Authorization: Bearer $LW_VK"
```

Expected: a `200` with a `data` array of models the key can route to.

## 7. A completion goes through

```bash
curl -sS https://gateway.acme.com/v1/chat/completions \
  -H "Authorization: Bearer $LW_VK" \
  -H "Content-Type: application/json" \
  -d '{"model":"openai/gpt-5-mini","messages":[{"role":"user","content":"ping"}]}'
```

Expected: a `chat.completion` object from the provider. The response carries `X-LangWatch-Gateway-Request-Id`, the id to search for in [Trace Explorer](/ai-gateway/observability).

Then confirm the request produced a spend record:

```bash
kubectl -n langwatch run curl --rm -it --image=curlimages/curl --restart=Never \
  -- curl -sS http://langwatch-gateway/metrics | grep gateway_spend_spool
```

Expected: `gateway_spend_spool_appended_total` is at least 1 and `gateway_spend_spool_dropped_total` is 0.

## 8. The control plane knows the public URL

The control plane hands the gateway URL to CLI users at sign-in. It reads `LW_GATEWAY_PUBLIC_URL`, which the chart sets from `gateway.publicUrl` or derives from `gateway.ingress.host`.

```bash
kubectl -n langwatch get deploy langwatch-app \
  -o jsonpath='{.spec.template.spec.containers[0].env[?(@.name=="LW_GATEWAY_PUBLIC_URL")].value}'
```

Expected: `https://gateway.acme.com`. An empty result means the ingress host is still the chart placeholder; set `gateway.ingress.host` or `gateway.publicUrl` and upgrade.

Members can then sign in from the CLI and get a [personal key](/ai-gateway/governance/personal-keys) bound to this gateway.
