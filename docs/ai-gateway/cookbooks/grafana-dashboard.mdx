The JSON below builds nine rows that an on-call engineer reads top down, from caller impact to the cause. Every panel reads a metric the gateway registers, so it works against any Prometheus that scrapes `/metrics`.

Pair it with [Prometheus alerts](/ai-gateway/cookbooks/prometheus-alerts) for the paging rules, and [Troubleshooting](/ai-gateway/troubleshooting) for the fix behind each row.

## What it covers

Nine rows, top to bottom:

| Row | Panels | What it answers |
|---|---|---|
| Request health | rate, p50, p95, p99, 5xx share | Is this affecting callers? |
| Provider health | circuit state, upstream latency, fallback events | Which credential is degrading, and is fallback covering it? |
| Auth cache | hit rate, resolve-key round trips | Is cache pressure loading the control plane? |
| Budgets | blocks by scope, spend records written and dropped | Which scope is rejecting traffic, and is spend reaching the ledger? |
| Guardrails | verdicts by direction, blocks by direction | Policy enforcement against a policy regression |
| Streaming | active streams, guardrail fail-open rate | Concurrency, and chunks passing through unchecked |
| Prompt cache | hit and miss rate | Whether provider cache reads are happening at all |
| Infrastructure | replicas, CPU, memory, goroutines | The Kubernetes side of everything above |
| Lifecycle | draining pods, in-flight requests | A stuck drain, before the kubelet kills the pod |

## Prerequisites

- Grafana 10.0 or later. The JSON uses time series panels and `$__rate_interval`.
- A Prometheus data source that scrapes the gateway's `/metrics`.
- `kube-state-metrics` and cAdvisor for the infrastructure row. Skip that row without them.

## Read it top down

1. **Request health.** Latency and the 5xx share together answer whether callers are affected.
2. **Provider health.** An open circuit means the gateway is skipping a credential. Fallback events next to it say whether another credential is covering the traffic.
3. **Auth cache.** Latency up with providers healthy points at cache misses and the control-plane round trips they cost.
4. **Budgets.** Blocks climbing on a scope means a hard cap is rejecting traffic. Spend records dropped means budgets are being enforced against incomplete spend.
5. **Guardrails.** `direction` and `verdict` separate policy working from policy going too wide.
6. **Streaming.** Active streams is concurrency. The fail-open rate is chunks passing through unchecked, which is by design on the stream-chunk direction.
7. **Prompt cache.** A prefix-heavy workload with near-zero hits means the provider is not reading its cache.
8. **Infrastructure.** Goroutines climbing and never falling is a leak. Replicas and CPU connect autoscaler pressure to everything above.
9. **Lifecycle.** A pod with `gateway_draining` at 1 and a flat in-flight count is a stuck handler that the kubelet will kill.

## Link it from your alerts

Put the dashboard URL in each alert's `runbook_url`, or in the notification body:

```yaml
receivers:
  - name: slack-gateway
    slack_configs:
      - channel: '#ai-gateway-alerts'
        title: '{{ .CommonAnnotations.summary }}'
        text: |
          {{ .CommonAnnotations.description }}

          <https://grafana.internal/d/langwatch-ai-gateway|Dashboard>
```

The engineer lands on the dashboard, narrows the cause to one row, then opens the matching section of [Troubleshooting](/ai-gateway/troubleshooting).
