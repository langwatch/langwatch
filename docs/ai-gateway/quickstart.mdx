## Before you start

You need:

- A LangWatch account with a project.
- One provider credential under **Settings > Model Providers**, for example your OpenAI API key. The gateway uses the credentials already configured there. See [Providers](/ai-gateway/providers/overview).
- The `virtualKeys:create` permission in the project. Project admins and members have it by default. See [RBAC](/ai-gateway/rbac).

## 1. Create a virtual key

1. Open **AI Gateway > Virtual Keys** and click **New virtual key**.
2. Enter a name, for example `acme-support-agent`.
3. Keep **Ownership** on **Project**. Traces and costs of this key land in the selected project.
4. Optionally set a **Budget**, for example `$50` per month. The key is blocked at the limit.
5. Keep **Provider access** on **All providers**, or select the providers this key may reach.
6. Click **Create**.

## 2. Send a request

Point the OpenAI SDK at the gateway and use the virtual key as the API key. Name the model as `provider/model`, for example `openai/gpt-5-mini`. A bare `gpt-5-mini` also works when one of the key's providers serves it.

<CodeGroup>

```bash curl
curl https://gateway.langwatch.ai/v1/chat/completions \
  -H "Authorization: Bearer $LANGWATCH_VIRTUAL_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5-mini",
    "messages": [{"role": "user", "content": "Say hi in one word"}]
  }'
```

```python Python
from openai import OpenAI

client = OpenAI(
    base_url="https://gateway.langwatch.ai/v1",
    api_key="vk-lw-...",  # your virtual key
)

response = client.chat.completions.create(
    model="openai/gpt-5-mini",
    messages=[{"role": "user", "content": "Say hi in one word"}],
)
print(response.choices[0].message.content)
```

```typescript TypeScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://gateway.langwatch.ai/v1",
  apiKey: process.env.LANGWATCH_VIRTUAL_KEY,
});

const response = await client.chat.completions.create({
  model: "openai/gpt-5-mini",
  messages: [{ role: "user", content: "Say hi in one word" }],
});
console.log(response.choices[0].message.content);
```

</CodeGroup>

The response is a normal OpenAI chat completion. The gateway adds these response headers:

| Header | Value |
|---|---|
| `X-LangWatch-Gateway-Request-Id` | The id of this request. Search it in Trace Explorer or quote it to support. |
| `Traceparent` | The W3C trace context of the span the gateway recorded in your project. Send your own `traceparent` header on the request to nest that span in your trace. |
| `X-LangWatch-Budget-Warning` | Present when a budget on this key is at 80 percent or more, as `scope:percent`. |

For the Anthropic SDK, set `base_url="https://gateway.langwatch.ai"` and the virtual key as `api_key`. The SDK sends the key in the `X-Api-Key` header, which the gateway accepts. See [Python SDK](/ai-gateway/sdks/python) and [TypeScript SDK](/ai-gateway/sdks/typescript).

## 3. Open the trace

Open **Trace Explorer** in the project you selected under Ownership. The request appears as a `gen_ai.chat` span with the model, the tokens, the cost and these attributes:

| Attribute | Meaning |
|---|---|
| `langwatch.virtual_key_id` | The key that served the request. |
| `langwatch.gateway_request_id` | The same id as the `X-LangWatch-Gateway-Request-Id` header. |
| `langwatch.model_provider_id` | The provider credential that served the request. |
| `langwatch.end_user_id` | The end user of your product, when the request carried one. See [Billing and spend events](/ai-gateway/billing-events#attribution-what-the-request-carries). |

## 4. See the spend

Open **AI Gateway > Usage** for total spend, requests, cost per request, top virtual keys and top models over the selected period. The **Virtual Keys** list shows a **Spent this month** column per key, and clicking it opens Usage filtered to that key.
