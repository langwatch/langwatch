<Note>
  **Available on Enterprise plans.** SCIM provisioning needs an Enterprise plan, and a self-hosted deployment needs an Enterprise license. The plan is checked on every SCIM call, so when it lapses, existing tokens stop verifying and your identity provider's requests are refused with HTTP 403. The [SCIM Tokens API](/api-reference/scim-tokens/overview) refuses to mint a token without an Enterprise plan with HTTP 402 and the error code `enterprise_plan_required`. To enable it, contact [enterprise@langwatch.ai](mailto:enterprise@langwatch.ai).
</Note>

SCIM (System for Cross-domain Identity Management) 2.0 lets your identity provider create LangWatch users when people join your organization, deactivate them when they leave, and push groups that you map to roles.

## Prerequisites

- `organization:manage` in LangWatch (an organization Admin)
- An identity provider that supports SCIM 2.0: Okta, Entra ID (Azure AD) and others
- SSO set up for your organization. LangWatch creates an SSO connection for your organization during SSO setup, and every SCIM token belongs to one connection. See [SSO Setup](/self-hosting/configuration/sso)

## Set up SCIM

### Step 1: Copy the SCIM base URL

Open **Settings > SCIM Provisioning**. The base URL is shown at the top of the page:

```
https://<your-langwatch-domain>/api/scim/v2
```

On LangWatch Cloud the domain is `app.langwatch.ai`. On a self-hosted deployment it is your own domain. The rest of this page writes it as `<your-langwatch-domain>`.

### Step 2: Create a bearer token

A token belongs to one SSO connection and is shown once. Create it through the [SCIM Tokens API](/api-reference/scim-tokens/overview) with the connection id LangWatch gave you during SSO setup:

```bash
curl -X POST https://<your-langwatch-domain>/api/scim-tokens \
  -H "Authorization: Bearer sk-lw-..." \
  -H "Content-Type: application/json" \
  -d '{"connectionId": "YOUR_CONNECTION_ID", "description": "Okta SCIM integration"}'
```

The response carries the token once. Store it in your identity provider straight away.

<Warning>
  The token cannot be retrieved later. If you lose it, revoke it and create a new one.
</Warning>

You can create several tokens, for example one per integration, and revoke each one separately from the table on **Settings > SCIM Provisioning**.

### Step 3: Configure your identity provider

| Setting | Value |
|---------|-------|
| SCIM Base URL | `https://<your-langwatch-domain>/api/scim/v2` |
| Bearer Token | The token from step 2 |

Where to enter them:

- **Okta**: [Configure SCIM provisioning](https://help.okta.com/en-us/content/topics/apps/apps_app_integration_wizard_scim.htm)
- **Entra ID (Azure AD)**: [Configure automatic user provisioning](https://learn.microsoft.com/en-us/entra/identity/app-provisioning/configure-automatic-user-provisioning-portal)

## Supported operations

| Operation | Description |
|-----------|-------------|
| **Create User** | Creates the user and adds them to your organization as a Member. An address that is already a member gets `409 Conflict` |
| **Get User** | Returns one user by id |
| **List Users** | Lists the users in the organization, with an optional `userName eq` filter |
| **Update User (PUT)** | Replaces the user's attributes |
| **Update User (PATCH)** | Changes single attributes, for example `active` |
| **Delete User** | Removes the membership and deactivates the account. The user's data stays |

### SCIM endpoints

| Endpoint | Methods |
|----------|---------|
| `/api/scim/v2/Users` | `GET`, `POST` |
| `/api/scim/v2/Users/{id}` | `GET`, `PUT`, `PATCH`, `DELETE` |
| `/api/scim/v2/Groups` | `GET`, `POST` |
| `/api/scim/v2/Groups/{id}` | `GET`, `PUT`, `PATCH`, `DELETE` |
| `/api/scim/v2/ServiceProviderConfig` | `GET` |
| `/api/scim/v2/ResourceTypes` | `GET` |
| `/api/scim/v2/Schemas` | `GET` |

`ServiceProviderConfig`, `ResourceTypes` and `Schemas` need no token. List endpoints return at most 100 rows per page; `startIndex` starts at 1. `ServiceProviderConfig` advertises `patch`, `filter` with `maxResults` 100, and no `bulk`, `sort`, `etag` or `changePassword`. `GET /Groups` accepts `excludedAttributes=members`.

### User attributes

| SCIM attribute | LangWatch field | Notes |
|----------------|-----------------|-------|
| `externalId` | Identity provider id | The primary key. LangWatch matches a user on the connection and `externalId` first, then on the email |
| `userName` | Email address | Must be an email. It is the account's address |
| `name.givenName`, `name.familyName` | Name | Joined into the display name |
| `emails` | | Accepted and ignored on write; the address comes from `userName`. Returned on read |
| `active` | Account status | `false` deactivates the user |
| `urn:ietf:params:scim:schemas:extension:enterprise:2.0:User` `costCenter` | Department | Assigns the user to the department with that name, and creates it when it does not exist. An empty value removes the assignment |

## User lifecycle

### Provisioning (Create)

- A new address: LangWatch creates the account and adds it to your organization as a Member.
- An existing account that is not in your organization: LangWatch adds it as a Member. A deactivated account is reactivated first.
- An existing member: `409 Conflict`.

Set the roles after provisioning in [Access Control (RBAC)](/platform/rbac), or map roles to groups with [SCIM Groups](/platform/scim-groups).

### Deprovisioning (Delete)

A `DELETE` on a user:

- Removes the organization membership and every role binding
- Deactivates the account. Every session and CLI token is revoked at once
- Keeps the user's data: traces, annotations and datasets
- A second `DELETE` returns `404 Not Found`

### Suspending (`PATCH active: false`)

- Deactivates the account. Every session and CLI token is revoked at once
- Keeps the organization membership and the role bindings
- `active: true` restores access

<Info>
  Use `active: false` for a temporary suspension and `DELETE` for permanent offboarding. After a `DELETE`, provisioning the user again starts with no bindings.
</Info>

## Manage tokens

**Settings > SCIM Provisioning** lists the tokens of the organization:

| Column | Description |
|--------|-------------|
| Description | The label given when the token was created |
| Created | When the token was created |
| Last Used | The last SCIM request authenticated with the token |

To revoke a token, click the delete icon on its row and confirm. The identity provider using that token loses access at once. The [SCIM Tokens API](/api-reference/scim-tokens/overview) lists and revokes tokens too, and each token created or revoked through the API is written to the [Audit Log](/platform/audit-log). Provisioning requests themselves are not in the audit log.

## Security

- **Rotate tokens**: create the new token and update your identity provider before you revoke the old one
- **One token per integration**: revoke one without affecting the others
- **Combine with SSO**: provisioned users then sign in through your identity provider
- **Watch Last Used**: a token with no recent use can be revoked

## Troubleshooting

**The connection test fails in the identity provider**

- The base URL ends with `/api/scim/v2`, without a trailing slash
- The token is pasted without extra whitespace
- The token is not revoked in LangWatch and the plan is active

**Users are not provisioned**

- The users or groups are assigned to the application in the identity provider
- **Create Users** is enabled in the provisioning settings
- The provisioning log of the identity provider shows the error LangWatch returned

**Generate Token on the settings page reports "Failed to generate token"**

- The button on **Settings > SCIM Provisioning** sends no SSO connection, and a token needs one. Create the token through the [SCIM Tokens API](/api-reference/scim-tokens/overview) with your `connectionId`, as in step 2. The page still lists and revokes tokens

**A user shows an "already exists" error**

- The address is already a member of the organization. LangWatch returns `409 Conflict`, and the identity provider links the existing user on its next sync
