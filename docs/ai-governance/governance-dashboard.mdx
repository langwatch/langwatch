`/governance` is the entry page for AI Governance. It opens with a greeting, a field for asking a question or jumping to a screen, **Add Source** for admins who can manage ingestion sources, and shortcuts to add people, an agent or a tool.

The page also shows **Insights** and **Recent activity** lists. Before your first source reports an event, each list says what will appear there.

The overview page does not read every governance metric itself. Costs, Inventory, Agents and People each own their own data, permissions and empty states.

## Where to find each number

| To see | Go to |
|---|---|
| Provider bills, LangWatch AI Gateway metering, seats and spender breakdowns | [Costs](/ai-governance/costs) |
| The tool catalog, environments and connected activity sources | [Inventory](/ai-governance/inventory) |
| Agents and AI applications detected across the organization | [Agents](/ai-governance/agents) |
| People, departments and spend attribution labels | [People](/ai-governance/people) |

## When admins land here

LangWatch can send an organization admin to `/governance` when the organization has active governance setup. The signal includes personal keys, routing policies, ingestion sources and recent governance activity.

Application traces alone do not make AI Governance the landing page. An organization that only uses LLMOps project traces still opens on its project workspace.

## Permissions

Opening `/governance` needs `governance:view`, which an organization Admin holds by default.

The screens linked from the overview can require narrower permissions. For example, Costs needs `governanceCost:view`, and source management uses `ingestionSources:view` or `ingestionSources:manage`.
