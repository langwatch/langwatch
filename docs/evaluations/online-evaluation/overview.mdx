Online evaluation is the production half of evaluation. Experiments test a prompt on a dataset before you ship it; a monitor scores the traces your live application sends, so you see quality and safety problems on real traffic, and you collect the failing cases to fix. To test before deployment, see [Experiments](/evaluations/experiments/overview).

## How it works

```
User request → Your application → Response → Trace in LangWatch → Monitor → Score
                                                                       ↓
                                                     Trace drawer, analytics, automations
```

1. Your application sends traces to LangWatch through an SDK or OpenTelemetry.
2. Each monitor checks its preconditions and its sampling rate against the incoming trace.
3. The monitor runs its evaluator on the trace, or on the whole thread once the thread goes idle.
4. The result lands on the trace and in the evaluations analytics, where an automation can pick it up.

The evaluator runs after the response is sent. A monitor never delays or blocks a response. To block a request, run the evaluator as a [guardrail](/evaluations/guardrails/overview) from your code.

## When to use online evaluation

| Use case | Example |
|----------|---------|
| Quality monitoring | An LLM-as-a-Judge with your criteria scores every conversation, and the pass rate trend shows a regression after a deploy. |
| Safety monitoring | PII detection, jailbreak detection or content moderation flags the traces that need a look. |
| Dataset building | An automation adds the traces a monitor failed to a dataset, so the next experiment runs on real failures. |
| Thread-level checks | A judge reads the whole conversation once it goes idle and checks whether the user's problem was resolved. |

## Monitors and guardrails

| Monitors | Guardrails |
|----------|------------|
| Score quality asynchronously | Block harmful content before it reaches the user |
| Run after the response is sent | Run inside your request, from your code |
| Feed the trace, analytics and automations | Return a pass or fail your code acts on |

## Create a monitor

1. Open [Online Evaluations](https://app.langwatch.ai/@project/online-evaluations) and click **New Online Evaluation**.
2. Pick an evaluator category and an evaluator, name it and map its inputs to the trace.
3. Pick **Trace Level** or **Thread Level**, add preconditions and a sampling rate if you need them, and click **Create Online Evaluation**.

The full walkthrough, with the thread-level options and where the results show, is in [Setting up Monitors](/evaluations/online-evaluation/setup-monitors).

## Add scores from your code

Your own code can record an evaluation result on the current span, next to the results of the monitors:

<Tabs>
  <Tab title="Python">
```python
import langwatch

@langwatch.trace()
def my_llm_app(user_input):
    response = generate_response(user_input)

    langwatch.get_current_span().add_evaluation(
        name="response_quality",
        passed=True,
        score=0.95,
        details="High quality response",
    )

    return response
```
  </Tab>
  <Tab title="TypeScript">
```typescript
import { getLangWatchTracer } from "langwatch";

const tracer = getLangWatchTracer("my-app");

await tracer.withActiveSpan("my_llm_app", async (span) => {
  const response = await generateResponse(userInput);

  span.addEvaluation({
    name: "response_quality",
    passed: true,
    score: 0.95,
    details: "High quality response",
  });

  return response;
});
```
  </Tab>
</Tabs>
