---
title: Setting up Monitors
description: Create an online evaluation that scores every incoming trace or thread with an evaluator, filter and sample the traffic it runs on, and read the results on the trace and in analytics.
---

A monitor is an evaluator attached to your production traffic. Every trace that matches its preconditions and sampling rate is scored as it arrives, asynchronously, so the score never delays the response to your user.

This guide sets up an LLM-as-a-Judge monitor named `Off-topic reply` that flags replies that drift away from the customer's question. The same steps apply to any evaluator, for example PII detection or jailbreak detection.

## Prerequisites

- Your application sends traces to LangWatch. See the [integration quick start](/integration/quick-start).
- For evaluators that call a model, a model provider configured in Settings.

## Create a monitor

<Steps>
<Step title="Pick an evaluator">
Open [Online Evaluations](https://app.langwatch.ai/@project/online-evaluations) and click **New Online Evaluation**. In the drawer, pick the **Evaluation Level**, then click **Select Evaluator**. Pick one of your saved evaluators, or click **New Evaluator** to open **Choose Evaluator Category**: **Expected Answer**, **LLM as Judge**, **RAG Quality**, **Quality Aspects** and **Safety**, plus **Custom (Code)** for a Python evaluator and **Custom (from Workflow)** for a workflow.

Pick **LLM as Judge**, then **LLM-as-a-Judge Boolean Evaluator**.

<Frame>
<img src="/images/evaluations/online-evaluation-category.png" alt="The Choose Evaluator Category drawer" />
</Frame>
</Step>

<Step title="Configure the evaluator">
Name the evaluator, pick the judge model and write the criteria in **Prompt**, for example: the reply passes only when it answers the customer's question and stays on the topic of the customer's order. A built-in evaluator such as PII Detection shows its own options here instead, for example the entity types to flag.

Under **Variables**, map the evaluator's fields to the trace. `input` maps to the trace input and `output` to the trace output by default. Click **Create Evaluator**.
</Step>

<Step title="Set the level, the filter and the sampling">
Back in the **New Online Evaluation** drawer, the evaluator is selected.

<Frame>
<img src="/images/evaluations/online-evaluation-drawer.png" alt="The New Online Evaluation drawer with the evaluation level, the evaluator, the name, a precondition and the sampling rate" />
</Frame>

| Field | What it does |
|-------|--------------|
| **Evaluation Level** | **Trace Level** scores each trace on its own as it arrives. **Thread Level** scores all traces of a thread together. See [Evaluate whole threads](#evaluate-whole-threads). |
| **Name** | The name shown in the list, on the trace and in analytics. |
| **Preconditions** | Optional. Click **Add Precondition** to run the monitor only on traces that match. Each rule reads a field from the trace, its metadata, its spans, its topics, earlier evaluations, events or annotations, and applies **contains**, **does not contain**, **matches regex** or **is**. With no precondition, the monitor runs on every trace. |
| **Sampling** | Optional. The share of matching traces to score, from `0.01` (1%) to `1.0` (100%). Lower it on expensive evaluators. |

Click **Create Online Evaluation**. The monitor is active as soon as it is created.
</Step>
</Steps>

## Evaluate whole threads

A trace is one request and response. A thread is the whole conversation, grouped by the `thread_id` you send in the trace metadata. Some checks only make sense on the conversation: whether the user's problem was resolved, whether the assistant stayed consistent across turns, whether the tone drifted.

Pick **Thread Level** in the drawer. The evaluator's variables now map to the **Current Thread** source, whose `traces` field holds every trace in the thread with its input and output.

<Frame>
<img src="/images/evaluations/online-evaluation-thread-level.png" alt="The drawer with Thread Level selected and the Thread Idle Time select" />
</Frame>

**Thread Idle Time** sets how long the monitor waits after the last message before it scores the thread, from 1 to 30 minutes, 5 minutes by default. Without it the thread would be scored again on every new message. Pick **Disabled - evaluate on every trace** to score after each message anyway.

## Read the results

On a trace, the **Evals** section of the trace drawer lists each monitor that ran with its verdict, score and the reason it returned, and the header shows an **Eval** chip per monitor. The trace table has an **Evals** column too, so you can filter and sort the [Trace Explorer](https://app.langwatch.ai/@project/traces) by the monitor's result.

<Frame>
<img src="/images/evaluations/trace-evals.png" alt="The Evals section of a trace drawer with the Off-topic reply verdict" />
</Frame>

The [Online Evaluations](https://app.langwatch.ai/@project/online-evaluations) list shows every monitor with its mode, its status and **Performance, last 7 days**: the pass rate or the average score with a trend against the previous week.

<Frame>
<img src="/images/evaluations/online-evaluations-list.png" alt="The Online Evaluations list with the active Off-topic reply monitor and its 7 day pass rate" />
</Frame>

**View analytics** in the row menu opens the evaluations analytics page with the pass rate trend, the average score and the overall pass and fail trend per monitor.

<Frame>
<img src="/images/evaluations/online-evaluation-analytics.png" alt="The evaluations analytics page with the pass rate trend of a monitor" />
</Frame>

## Pause, edit and remove a monitor

The row menu on the list has **Edit**, **Disable** (or **Enable** on a paused monitor), **Replicate to another project** and **Delete**. A paused monitor keeps its history and stops scoring new traces.

## Act on the results

- To be notified when a monitor fails, create an automation on the evaluation result. See [Automations](/features/automations).
- To collect the flagged traces into a dataset, add an automation with the **Add To Dataset** action. See [Build datasets from traces](/datasets/automatically-from-traces).
- To block a request before the response reaches the user, run the evaluator as a guardrail from your code instead of as a monitor. See [Guardrails](/evaluations/guardrails/overview).

**Also check:** [Evaluators](/evaluations/evaluators/overview) for the full list of evaluators a monitor can run, and [Saved evaluators](/evaluations/evaluators/saved-evaluators) to reuse one evaluator across experiments and monitors.
