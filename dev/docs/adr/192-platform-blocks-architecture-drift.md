# ADR-182: The platform blocks architecture drift, not a reviewer

**Date:** 2026-10-20

**Status:** Accepted

## Context

A review of four analytics and insight pull requests, and of the pull requests merged in the two
weeks before, found the same mistakes again and again: a raw colour beside the design system's
tokens, a peer module's screen address or error code spelled as a literal, a file copied
byte-for-byte into a second module, a model's table read by a module that does not own it, a
library folder no rule knew about, and a component re-built from Chakra primitives. Each one
passed review. `dev/docs/ARCHITECTURE.md` described most of them as wrong, but prose grants nothing:
nothing in CI refused them, so the author decided, and ticked a box saying they had read the record.

A human reviewer as the gate does not scale, and makes one person the bottleneck for every module.

## Decision

Every architecture rule is a blocking check. There is no code-owner review, no required approval
and no sign-off register. A rule joins CI at zero findings; where clearing main in one change is
not reasonable, the policy still reports every finding and a shrink-only list
(`dev/docs/ARCHITECTURE.md` §17, "Shrink lists") holds today's count per key, refusing growth and
refusing a count that should have fallen.

A change that makes a decision no check makes (new architecture prose, a lint suppression, a new
package or module, a removed rule or policy, a widened exemption, a grown shrink list, a raised
budget) must record, in the pull request's `## Architecture` section, the options shown to the
human the author works for, the human's choice, and the rule that now encodes it
(`.github/scripts/guard-architecture-section.ts`, `specs/ci/pr-architecture-section.feature`). The
author asks; it does not decide.

The module library kind is deleted: a module owns a contract, a process, a browser and a client,
and nothing else. A client lends a component token as a ready component (`lentComponent`), so a
borrower writes no wrapper.

## Consequences

- An agent that meets a case no rule covers stops and asks its human, and the answer becomes a
  rule. The next change is decided by a check.
- Shrink lists are worked down by the tech-debt bot, one key per pull request, and by anyone
  touching the code; none may grow.
- `XError.is(error)` matches any handled error carrying `XError.code`, across processes and the
  wire. While `error-code-single-owner` still lists a code as declared by several classes, `.is()` on
  one of them also matches its siblings, whose `meta` may differ; read fields through
  `readHandledError`, and shrink that list rather than relying on the class.
- A heuristic rule (duplicates, fan-in, timing) can flag code a human would accept. The answer is
  to narrow the rule in the open, which the guard records, not a quiet exemption.
