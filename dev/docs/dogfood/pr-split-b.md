# Git branches, rebases, and merges

A git branch is a movable pointer to a commit. It lets you work on a line of history without changing the main line. Creating a branch is cheap, since it only adds a new pointer, not a copy of the files. The default branch is often called main, and most teams treat it as the stable line of history. You create a new branch to isolate work such as a feature or a bug fix. You switch between branches with `git checkout` or `git switch`, and each switch updates your working files to match that branch's commits.

A merge takes the changes from one branch and combines them into another. Git creates a merge commit that has two parent commits, one from each branch, so the history keeps a record of both lines joining. A rebase takes the commits from one branch and replays them on top of another branch, one by one. This produces a straight line of history, since it does not add a merge commit. Rebasing rewrites commit hashes, so you must never rebase a branch that other people have already pulled and are working on. Merging is safer for shared branches, while rebasing is useful for cleaning up your own local history before you share it.
