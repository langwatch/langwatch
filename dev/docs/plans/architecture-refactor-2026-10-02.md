## What is wrong, by theme

### 1. Security

76 security findings are tracked privately, not in this file.

### 2. Swallowed failures that report success

Governance ingest swallows log, budget and ledger failures, and the plan check maps any error to "not entitled". Billing:

- Checkout completion swallows invite approval, currency and threshold failures, and Stripe gets a 200.
- Stripe redeliveries are reprocessed in full: no processed-event store, so licences are minted again.
- `reportUsageForMonth` returns `[]` on any error.

Elsewhere:

- Project archive deletes objects before the archive write, and ignores cleanup failure.
- The report-dispatch `recordFire` failure is only warned, so reports go out twice.
- Nine `.catch(() => undefined)` in hosted-mcp cleanup.
- About 25 in scenarios.
- Experiment rollback `.catch(() => undefined)`, and a JSON parse failure overwrites targets.
- Demo-data "succeeds" while seeding nothing.

**Proper:** the user's rule. A recoverable failure goes back as a handled error with useful but not exposing detail. Every bad one is logged well, and none report success.

### 3. Crossing module boundaries

- **Tables written by non-owners** (ADR-134: write from the owner, read elsewhere via its Api):

- **Tables read by non-owners:**

  - analytics reads trace_summaries, trace_analytics(_rollup), stored_spans and evaluation_runs.
  - governance runs raw ClickHouse on trace_summaries from a `prisma.*` file.
  - ops reaches process-store tables in 28 places.
  - **Proper:** typed reads on TraceApi and EvaluationApi; the owner supplies its subquery.
- **Peer cycles (267).** Untangle the billing ↔ licensing ↔ gateway ↔ entitlement knot first. Then project, feature-flag, onboarding and coding-agent, which pull in many Apis.
- **Framework packages holding per-module knowledge** (S14):

  - The ClickHouse TTL table list.

- **Data access outside repositories:** role.app.ts queries team and project; also gateway, ops and stored-object compositions, storage-meter.service.ts, tenant-directory.ts and the lwql-provision task.

  - 106 restate the default.
  - 63 set `retry: false`.

  - **Proper:** caching lives in the client and the read's tier, not per call.
