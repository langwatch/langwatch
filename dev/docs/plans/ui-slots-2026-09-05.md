# A core screen asks for an enterprise block; it never imports one

Status: design frozen 2026-09-05 (Alex: "create it"). Closes the nine
core-to-enterprise component imports `langwatch(package-boundaries)` reports,
the last cross-feature web bucket the `ui-host` capabilities design left open.

## Today

Nine core web modules name an enterprise package directly:

```
features/gateway/web        ─┐
features/authz/web          ─┼─► @langwatch/enterprise-billing-web/surfaces/contact-sales
features/organization/web   ─┘        (ContactSalesBlock, 4 call sites)

features/organization/web   ───► @langwatch/enterprise-licensing-web/surfaces/seat-types
                                      (LITE_MEMBER_*, SEAT_TYPES_DOC_PATH, 3 call sites)
features/organization/web   ───► @langwatch/enterprise-licensing-web/surfaces/resource-limits
                                      (ResourceLimitRow, LIMIT_TYPE_DISPLAY_LABELS)
features/model-provider/web ───► @langwatch/enterprise-managed-provider-web
                                      (ManagedModelProviderAlert)
```

`packages/features/authz/web/src/ui/elements/enterprise-upsell.tsx` exists only
to make that cost ONE import line instead of two, and says so in its own header:
the import is a recorded cost waiting for a seam. This is the seam.

## End shape

A core screen asks the composition for a block by NAME and renders what comes
back, or its own fallback when nothing came back. Only `apps/ui` — the one
package that may name both halves — decides what comes back.

```
 packages/features/*/web            packages/ui-host              apps/ui
 ────────────────────────           ────────────────              ───────
 <UiSlot name="contactSales"        slots.tsx                     features/billing/ui/sections/
         props={{}} />        ──►   ┌──────────────────────┐        billing-slots.ts
        │                           │ UiSlotsPort          │      features/licensing/ui/sections/
        │  useUiSeatTypeCopy() ──►  │  filled(name)        │        licensing-slots.ts
        │                           │  seatTypeCopy()      │      features/model-provider/ui/
        ▼                           │                      │        sections/model-provider-slots.tsx
   reads capabilities.slots  ◄──────┤ CORE_SEAT_TYPE_COPY  │              │ each declares its use in
   through the React context        │ UNFILLED_UI_SLOTS    │              │ features/catalogue.json
   published by the shell           └──────────────────────┘              ▼
                                             ▲                    installed-ui-features.ts
                                             │ type-only            slots: uiSlots({
                                    capabilities.ts                   components: {...three},
                                     UiCapabilities.slots?             seatTypeCopy: …,
                                     resolveUiCapabilities()         })
                                             ▲
                                             │ published by
                                    ui-feature-shell.tsx

 nothing filled the slot ─► render the fallback. Never a throw.
```

### `packages/ui-host/src/slots.tsx`

- `UiSlotProps` — one entry per rendered slot, typed by the props the CORE
  feature passes, not by the enterprise component's own signature:
  - `contactSales: Record<string, never>` — the block takes nothing.
  - `resourceLimits: { label: string; current: number; max?: number }`.
  - `managedModelProviderAlert: { provider: string; error?: string }` — the
    provider KEY, not enterprise's `ManagedModelProvider`; the fill adapts.
- `UiSeatTypeCopy` — the seat-type words as a record. Copy, not a component,
  so the slot answers data and `CORE_SEAT_TYPE_COPY` is the core default.
- `UiSlotsPort` — abstract class, both members defaulted: `filled(name)` reads
  `undefined`, `seatTypeCopy()` reads the core default. Degrading is the base
  behaviour, so an absent port and an unfilled slot are the same reading.
- `uiSlots({ components, seatTypeCopy })` — what a composition installs.
- `<UiSlot name fallback {...props} />` and `useUiSlot(name)` /
  `useUiSeatTypeCopy()` for the call sites that need the value, not an element.

### Where the fills live

`ui-web-capability-owner` refuses a feature-web surface imported from an
`apps/ui` module that belongs to no named frontend feature, so the fills sit in
the feature directory that owns the words — billing fills `contactSales`,
licensing fills `resourceLimits` and `seatTypeCopy`, model-provider fills the
managed-provider notice — and each declares its exact surface in
`apps/ui/src/features/catalogue.json`. `installed-ui-features.ts` merges the
three into the one `slots` capability.

`@langwatch/enterprise-managed-provider-web` had a bare `.` export and no
governance, which `ui-web-package-governance` refuses. It gains a
`surfaces/managed-provider-alert` entry, loses the `.` one, and joins
`governedWebPackages`, the same shape billing and licensing already have.

### `packages/ui-host/src/capabilities.ts`

`slots?: UiSlotsPort` joins `UiCapabilities`, and `resolveUiCapabilities`
passes `install.slots` through. It stays OPTIONAL and the import is
`import type`: capabilities must not gain a runtime edge to a module that
imports it back, and a hook that reads `capabilities?.slots ?? default` is
already the degrade the port describes.

### Copy: why the core default holds the real words

`seat-type-explanation.integration.test.tsx` renders the organization form with
no shell above it, so it reads the CORE default — and asserts the explanation
names traces, analytics, scenario runs and that costs are not visible. The core
default therefore carries the canonical sentence verbatim, and `apps/ui` fills
the slot from licensing's surface anyway, so the running application keeps
reading licensing's copy and the enterprise pinning test
(`seatTypeCopy.unit.test.ts`) keeps holding it against the permission list.
Two records with the same words is the recorded cost: the alternative is a core
package that cannot explain its own form without an enterprise dependency.

## Out of scope

- `packages/features/organization/web/src/ui/sections/member-seat-usage.tsx` —
  the only `resource-limits` consumer, held dirty by another lane on
  2026-09-05. The `resourceLimits` slot and its fill ship here; repointing that
  one file is a follow-up.
- `packages/enterprise/**` keeps its own direct imports: an enterprise screen
  naming an enterprise surface is not a boundary crossing.
