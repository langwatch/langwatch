# Architecture-lint burn-down plan

**Written:** 2026-09-03 on `feat/strict-feature-layout-v0`, read-only. **Input:** one full `pnpm --filter @langwatch/architecture-lint lint` run (2,946 violations across 41 policies) plus one `review:comment-blocks` run (20,137 blocks over the limit in 7,476 files; 10,298 in the 4–5 line warn tier). **Companion:** `architecture-lint-review-2026-09-03.md` (the rule-by-rule review this plan acts on).

Three lanes already own parts of this surface and are referenced, not re-planned: **I** = `install-composition-review-2026-09-03.md` (deletes `platform-api-contract` and `enterprise-web`, folds the apps/ui host adapters, one `uiPage` helper, and — queued behind it as post-merge item 4 — one `./install` export per feature web package); **T** = `trpc-flatten-design.md` (root `AppRouter`, `trpcReact` in every web package, api-maps deleted); **K** = the tasks launch interface (`tasks-launch-interface-and-saas.md`, owns `apps/tasks`); **ID** = the identity ADR-129 refactor.

## 0. Ground rules

1. **A finding is one of three things.** (a) the code is wrong: fix it, in a slice an agent can run without judgement; (b) the rule is wrong or redundant: change the rule; (c) the rule is right and the target is out of reach this week: a baseline is allowed only when it is **shrink-only, keyed by the thing that must go to zero (an edge, a file, a root), fails the gate when it grows or expires, and never exempts a changed file**. "Baseline the current output and move on" is not one of the three.
2. **Generated shape is fixed, not baselined.** The lift-and-shift produced three sloppy shapes: grab-bag `exports` maps on web packages (65 entries on `workflow-web`), flat `src/` trees in server packages (identity's 55 root files), and re-exported repositories on server roots. Every one of those is category (a) here.
3. **Repositories never reach a server package's surface.** Not from `index.ts`, not from `testing.ts` (§4). The door is an adapter static: `PostgresAuthzAdapter.createReader({ database })`.
4. **Comments help read the code.** Over 3 lines is reviewed, 5 is the maximum, history goes to an ADR. A JSDoc block is a comment.
5. **Agents move, they do not redesign.** Slices below name the transformation. Where a file does not fit the named class, the agent reports it and stops; it does not invent a placement (each wrong placement trades one violation for another — `strict-feature-source-layout-grammar` memory).
6. **Diff the violation list, not the total.** Every slice ends with `pnpm --filter @langwatch/architecture-lint lint > after.log 2>&1; diff <(grep '^\[' before.log) <(grep '^\[' after.log)`; a slice that adds any line is not done.
7. The root session runs the typecheck named per slice (`pnpm --filter <pkg> typecheck`), never a whole-tree one. Agents run the test command named per slice and nothing wider. No `git stash`, `restore`, `checkout --`, `reset`, `clean`; commit by explicit pathspec.

## 2. Rule changes (R slices)

All R slices live in `packages/architecture-lint`. Test: `pnpm --filter @langwatch/architecture-lint test`. Typecheck after: `@langwatch/architecture-lint`. Each rule change is written test-first against the package's fixtures (`tests/`), and each one that widens an allowance names the allowance in the rule's own header comment in ≤3 lines.

### R1 — comment-blocks: tiers, default scan, root allowlist with expiry

Files: `src/comment-blocks.ts`, `src/cli.ts`, `src/index.ts`, new `src/comment-block-roots.json`, `tests/comment-blocks.test.ts`, `tests/cli-comment-review.test.ts`.

What `pnpm lint` does after R1, on every run:

```
                 changed files (merge-base + working tree)          all other tracked source
                 ─────────────────────────────────────────          ────────────────────────
  6+ lines       ERROR, always                                      ERROR unless the file's root is
                                                                    in comment-block-roots.json and
                                                                    that entry has not expired
  4–5 lines      WARN, printed on stderr under a                    not scanned
                 "review" heading, exit code unchanged
  ≤3 lines       silent                                             silent
```

- **Warn tier becomes visible.** `cli.ts` prints `commentBlocks.reviews` for changed files on every run, not only under `--review-comment-blocks`. It does not change the exit code. This is how a 4–5 line block gets a second look at review time without a 10k-line listing.
- **Whole-repo error becomes real without listing 20k lines.** `comment-block-roots.json` lists roots (not files, not blocks) that still carry over-limit blocks, each with an `expires` date and the count at the time of writing: `{ "root": "packages/features/trace/web", "blocks": 1435, "expires": "2026-10-03" }`. A file under a listed, unexpired root is skipped by the whole-repo scan; a file anywhere else is scanned and fails at 6+. The file is shrink-only against the merge-base (an entry may be deleted, its `blocks` may go down, its `expires` may not move later); an expired entry fails the run with `comment-block-root-expired`. ~90 entries, one per root in §6's table.
- **Changed files are never exempt.** The allowlist only affects the whole-repo scan. A PR that touches a file in an allowed root still fails on that file's over-limit blocks; the agent clearing that file is the one paying, which is the point.
- **Per-file allowlist with expiry: acceptable in principle, wrong at this size.** 7,476 file entries is a 500 KB JSON nobody reads; roots are the unit the burn-down is scheduled by. When a root is under ~40 blocks, its entry may be converted to file entries so the last stragglers are named. Same expiry and shrink-only rules.
- **Scope.** No root is exempt, including `sdks/` (1,362) and `mcp/` (69). Published-package JSDoc is documentation for a user, but a 76-line JSDoc on a type is history; the SDK's documentation lives in `docs/` (Mintlify) and the JSDoc carries one line and a link. Test files are in scope (2,966 blocks); `@scenario` blocks are already exempt.
- Thresholds stay at 4 (warn) and 5 (max); nothing here changes what counts as a block.

### R7 — feature-layout grammar: `rules/` kind and migration names (decision gate)

File: `src/feature-layout.ts`, `SERVER_PATTERNS`; `dev/docs/best_practices/service-repository-adapter-port.md` gains the paragraph.

100 of the 303 layout violations are pure functions with no home: 55 `*.rules.ts`, 16 `canonicalisation/*.canonicaliser.ts`, identity's `*-guards.ts` / `*-id.ts`, analytics' `query-builders/*`, `clickhouse/*translator.ts`. The grammar today says a pure helper is a `.service.ts` class. That is the Java shape, and Alex's ruling is that the JavaScript should read like clean Go — a package of functions. **Decision requested: add exactly one kind, `rules/<subject>.rules.ts`.** Constraints the rule enforces: the file exports functions and constants only (no class, no `new`), and its imports resolve only to `*-contract` packages, other `rules/` files in the same package, `node:*`, and framework-free workspace packages already accepted by the portable oracle. A `rules/` file that imports a service, port, adapter, Prisma or ClickHouse fails `feature-source-layout` with a message naming the import. If the decision is "no", L2 below folds each `.rules.ts` into the service that calls it (as private methods, or a `<subject>.service.ts` class of static methods) — the same 100 files, different destination; the slice list does not change.

Also in R7: `migrations/${NAME}-import\.${NAME}\.migration\.ts` becomes `migrations/${NAME}\.migration\.ts` (identity's three migrations are named `identity-secret-heal.migration.ts`; the `-import.` infix describes one migration family, not the kind).

### R8 — boundary edge baseline (shrink-only)

New `src/boundary-edge-baseline.json`, read by `frontend-ui-boundaries.ts` (screen closure "feature-web public entry", `ui-web-public-entry` export rows) and `manifests.ts` (`cross-feature` web→web, `enterprise-direction` core→enterprise). One entry per **edge**: `{ "from": "@langwatch/trace-web", "to": "@langwatch/analytics-web/…", "expires": "2026-10-17" }`. Rules: an edge not listed fails as today; a listed edge is silent until it expires; the file may only lose entries or lower an expiry against the merge-base (same mechanism as `service-quality-baseline`); an edge whose `from` or `to` no longer exists fails as stale. Bootstrapped once from the current run after W1–W3 land (so the `workflow-web` grab-bag never enters it). Why this is not a dodge: the thing that must reach zero is the edge, the file is keyed by edge, growth fails, expiry fails, and the two fixes that drain it are named — W for the hub, and the surfaces design (`dev/docs/best_practices/feature-web-data-access.md` §"surfaces", to be written by the first owner who needs a cross-feature surface) for the 14 core→enterprise and ~60 web→web edges that are product structure, not lift-and-shift residue.

## 4. Ruling: repositories and `testing.ts`

## 6. Comment-block burn-down

### What an agent does with one block

Comment-only edits, plus ADR/doc appends. No code moves, no renames. Per block, top to bottom:

1. **History → delete.** "used to", "before #NNNN", "the old", "when the rename landed", "landed anyway", incident narrative, the reasoning that led to the current shape. If the paragraph records a decision that still governs the code and no ADR states it, append a dated section to the nearest ADR (`packages/features/<f>/adrs/` for a feature, `dev/docs/adr/` for repo-wide; never a new ADR number without checking `adr-number-collisions`) or to the matching `dev/docs/best_practices/*.md`, and the comment becomes one line: `// Ledger heads are append-only; see ADR-127.`
2. **Restating the code or the types → delete.** `@param database the database`, "This class is a service that…", a sentence per field.
3. **The invariant a reader needs to not break the code → keep, ≤3 lines, directly above the statement it guards.** "Why not the obvious thing" is the one kind of comment that earns its place.
4. **JSDoc on an exported symbol → one summary line.** Examples and long parameter prose move to `docs/` (Mintlify) for the SDK, or are deleted for internal code.
5. **`@scenario` blocks, lint directives, licence and generated headers → untouched** (already exempt).
6. **`TODO`/`FIXME` → one line with the issue number, or delete.**

Then: `pnpm --filter <package> test` for the touched package (some suites read source text — `source-reading-guards-die-on-moves` memory — so a comment edit can fail a test and that is a real signal), and the lint diff. Two-thirds of the blocks are `/**` JSDoc (2,043 of a 3,000-block sample); those are mostly class 4.

### Waves and slice sizing

200 blocks per slice (≈ 40–60 files); an agent finishes one in a sitting. ### Gate behaviour during the burn-down

After R1: `pnpm lint` fails on any 6+ block in a changed file (so C0 is a hard precondition for this branch to go green), prints 4–5 line blocks in changed files as review items, and fails on any 6+ block in a root that is not in `comment-block-roots.json` or whose entry has expired. Each C slice ends by deleting or lowering its root's entry. Expiry dates: C1 roots 2 weeks, C2/C3 4 weeks, C4/C5 6 weeks from the day R1 lands; an expired root fails the gate, which is what turns the schedule into a promise.

## 7. Redundancy with oxlint

`packages/architecture-lint/oxlint-plugin.mjs` ships `package-boundaries`, `environment-boundaries`, `service-classes`, `service-quality`, `service-dependencies`, `api-context-services`, `feature-module-classes`, `runtime-undefined`, `max-statements-per-line`, `service-member-spacing`, `logical-statement-spacing`, `boolean-wall`, `awaited-return-chain`. Overlap with this package's rules is by name only in two places: oxlint's `service-quality` is a per-file statement/complexity check without the shrink-only baseline (`service-quality.ts` owns the ceilings; the oxlint rule can be deleted or scoped to what the baseline does not measure — decide in R9 after reading both rule bodies side by side), and oxlint's `package-boundaries` reads import specifiers per file while `manifests.ts` reads `package.json` — complementary, keep both. Nothing in oxlint's built-in set measures comment blocks, layout, exports, or cycles; comment-block-size is not redundant with anything.

## 9. Deviations

- **R1's `comment-block-roots.json` is bootstrapped at file-role granularity (169 entries), not the ~90 feature-level entries §6's wave table sketches.** The table groups by feature (`trace`, `analytics`, …); the actual JSON is keyed one entry per package root (`packages/features/trace/web`, `packages/features/trace/server`, `packages/features/trace/contract` as three separate entries, not one `trace` entry), because that is the granularity `isStrictPrismaAdapter`-style root matching in `lintCommentBlocks` needs to stay a simple prefix test and the granularity a C-slice actually ships against (`@langwatch/trace-web`'s suite, not "trace" as a whole). Counts were measured directly (`lintCommentBlocks` over the full tree, grouped and summed), not transcribed from the plan's approximate wave figures, so a handful of entries differ slightly from §6 (e.g. `packages/features/trace/web` measured 1,435, matching; most others are within a few blocks). Expiry tiers follow §6 exactly: `apps/*` 2 weeks (2026-09-17), `packages/features/*` and `packages/enterprise/features/*` 4 weeks (2026-10-01), everything else (shared packages, `sdks/`, `mcp/`, `skills/`, `dev/`, `.github/`, `services/`, `docs/`, `plugins/`) 6 weeks (2026-10-15), all from 2026-09-03.
- **R1's shrink-only comparison against the merge-base is not exercised in the default `pnpm lint`.** It follows the existing `service-quality-baseline` / `port-module-baseline` pattern exactly: `lintCommentBlockRoots(root, reference)` only does the growth comparison when a `reference` file is passed (via `--comment-block-roots-reference` or `--baseline-reference-dir`), which CI supplies from the merge-base copy (the workflow's `for baseline in …` loop now includes `comment-block-roots.json`). A plain local `pnpm lint` run has no reference and so only enforces the tier logic and per-entry expiry, not growth — matching how the other two debt inventories already behave locally.
- **R9's optional item — replacing `legacy-application-boundary-baseline.json` with a flat `global-app-access` check — was left alone.** The plan itself marks it "Optional, same slice"; the file's four edge buckets are already empty (fully drained), so it currently costs nothing to keep, and swapping the mechanism is a design change outside a mechanical burn-down slice. Not attempted.
- **R7 (the `rules/` grammar decision) and R8 (the boundary edge baseline) are untouched, as instructed** — they wait on a ruling and on W1–W3 respectively. The A/L/Q/W/C code slices were not started, also as instructed.
