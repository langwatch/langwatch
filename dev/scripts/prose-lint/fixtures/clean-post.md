We moved our support bot's retrieval step onto LangWatch traces last month, mostly so we could see what the model was reading before it answered. The retriever calls Postgres full-text search over the help center, takes the top five chunks, and pastes them into the prompt under a `contexts:` header, so the trace shows the exact five chunks per answer.

The first week turned up 212 conversations where `contexts` was an empty list, which is roughly one answer in nine, and every one of them still got a confident reply. The cause was a `try/except` around the search call that returned `[]` on a timeout, and Postgres was timing out whenever the nightly index rebuild overlapped with European morning traffic. We moved the rebuild to 03:00 UTC and added a check that fails the answer when `contexts` is empty, which so far has fired eleven times in three weeks, all during a deploy.
