Langy's pi harness (`@earendil-works/pi-coding-agent@0.84.2`) tags every conversation entry with a role, and an extension provably cannot author a `role: "user"` one — which is what makes the planned structural delete gate (#7608) worth building, since it can require a genuine user confirmation rather than a self-authored passphrase (the #7562 bypass). That guarantee holds only for the live session: `getBranch()` walks an in-memory map, but on resume the session JSONL is re-parsed from disk (`session-manager.js:98`, `:269`) with **no integrity check** — no signature, hmac, or checksum anywhere in that file — and Langy holds the `write` and `bash` tools. So Langy can append a forged `role: "user"` "yes, delete it" line today and have it load as a genuine confirmation tomorrow; a second, related crack splices the previous worker's agent-authored digest *inside* the user's own message on resume (`services/langyworker/src/system-prompt.ts:43-53`). Both live on the resume path, and one rule closes both: the gate must bind assent to the current turn's in-memory entry and never trust branch history read off disk. Upstream-side this is the vendor's to fix properly (unauthenticated session store); ours is the workaround, and it should land before any gate is wired in.
