## Rulings, 2026-10-05 (Alex)

- **Drift is caught by lint, and the message is a prompt.** Wherever code drifts from the architecture direction (middleware doing what the API framework does, such as auth or JSON body parsing; routes opened to any authenticated or unauthenticated caller), a new lint rule catches it. The error explains, written to the agent reading it, why the shape is wrong and what to use instead.
- **House rules are strict; a disable is very rare.** Most `langwatch/*` rules must not be ignored: a disable directive naming one is itself an error.
- **A few named rules allow a justified disable.** Only rules where the framework may genuinely not cover a case (API middleware usage, opening a route to any caller) accept a disable, and only with a reason explaining why the framework cannot be used. A bare disable is an error. This is for the new rules, not a sweep of old directives.
- **When unsure, ask the human.** The message on those few rules tells the agent that if the case is confusing, it stops and asks the human rather than disabling.
- **Peer-cycle edges:** ask Alex before cutting or listing any of them.
- **Landing:** reviewed slices are committed and pushed directly to feat/strict-feature-layout-v0. First goal: get the branch's CI green.
